Lessons Learned

Things that failed, brilliantly.

Every data engineer has a graveyard of pipelines that ran perfectly in dev and silently corrupted data in production. Here's mine.

01
The Pipeline That Loved Duplicates
Forgot to implement idempotent upserts on the first pass. Re-ran the pipeline after a network timeout. Every row loaded twice.

Lesson: always design for safe re-runs from the start, not after discovering duplicates in production.
02
The Schema That Changed Overnight
An API returned a new field without notice. Downstream Pandas transformations silently dropped it. The data loaded cleanly — with missing columns.

Lesson: always validate schema on every run, not just the first one.
03
The API That Liked Rate Limits
Parallel fetches hit the API rate limit at 2am. No retry logic. The pipeline crashed silently and I woke up to empty tables.

Lesson: retry logic and backoff aren't optional in production ETL, they're the pipeline.
04
Logs That Said Nothing Useful
Built a pipeline, added a single print statement for logging. A failure happened somewhere in the middle. No timestamp, no stage, no context.

Lesson: structured logging from the start pays back every time something goes wrong.
APIs lie. Schemas drift. Data is never as clean as it looks.
